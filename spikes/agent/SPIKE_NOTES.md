## Other findings that shape the middleware (measured, not in s14)

- **`after_model` hooks run in reverse list order** (`factory.py`: `model -> middleware_w_after_model[-1]` then backwards). With doc 07 s2.5 order, `GroundingMiddleware` (item 9) runs first after the model, then the tool limiters, then `ModelCallLimitMiddleware`'s counter. A Gate 2 `jump_to: "end"` therefore skips the later `after_model` hooks; harmless (the run ends), but the model-call counter is not incremented for that call.
- **`stream_mode="messages"` also emits whole messages returned by hooks**: route lines (node `RouterMiddleware.before_model`), the model-limit line (node `ModelCallLimitMiddleware.before_model`), the Gate 2 line (node `GroundingMiddleware.after_model`). Since the adapter takes tokens only from node `model`, none of these leak as tokens; the adapter writes them from final state.
- **Draft tokens stream from node `model` before Gate 2 runs** (spike 6 output). The doc 07 s6.4 buffering rule in the adapter is required, not optional.
- **SDK error types**: both `langchain-anthropic` 1.7.13 and `langchain-openai` 1.8.5 raise subclasses of `langchain_core.exceptions` (`ModelRateLimitError`, `ModelAPIError`, `ModelTimeoutError`, `ModelInvalidRequestError`, ...) that also inherit the SDK error. Classify on these for the retry predicate and the `model.fallback.reason` mapping.
- Test noise: real-call tests print `RuntimeError: Event loop is closed` from httpx client teardown after the loop closes; tests still pass. Not a product concern (the service keeps one loop).
